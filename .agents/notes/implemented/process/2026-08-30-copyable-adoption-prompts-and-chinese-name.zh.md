# Agent Note：可复制接入提示语与中文展示名

Status: implemented
Date: 2026-08-30

[English](2026-08-30-copyable-adoption-prompts-and-chinese-name.md) | 中文

## 问题

可复用指南已经定义三种 `proposedMode` 和详细的新项目接入清单，但读者仍需自行把这些规则转换成给 Codex 或其他 Agent 的请求。指南也缺少稳定的中文展示名，导致中文引用在仓库名直译、“Agent Note 驱动开发工作流”和不够准确的描述之间变化。

## 决策

“AI Agent 决策记录工作流”作为推荐中文展示名，在需要明确仓库身份时同时显示 `ai-agent-note-workflow`。仓库名和英文术语保持不变。“决策记录”自然地涵盖 Note 中的问题、提案或决策、替代方案、验证、后果和生命周期历史。

两份 README 都在详细新项目接入清单之前提供“可复制的接入提示语”小节，按以下顺序明确展示三种用户选项：中文模式（`zh-only`）、英文模式（`en-only`）和双语模式（`bilingual`）。中文模式排在第一位并标记为新项目“推荐”，因为它能减少起草更新成本，同时在生命周期迁移边界保持双语收敛。这个文档推荐不改变校验器兼容行为：缺少配置的现有项目仍按 `bilingual` 处理。

每种模式都有一条可直接使用的提示语，包含上游仓库 URL、目标项目路径占位符、所选模式及其 proposed 阶段文件行为、生命周期迁移前补齐锁定双语三件套的要求，以及在不改变业务行为的边界内添加配置、Agent 规则、兼容校验器和项目检查集成的指令。

中文 README 提供中文提示语，英文 README 提供语义等价的英文提示语。这些提示语描述把工作流规则适配到下游项目，不暗示运行时软件包依赖、遥测、自动更新或持续同步上游。

## 考虑过的替代方案

**使用“AI Agent 注记工作流”。** 这更接近仓库基名，但“注记”不够自然，也弱化了这些记录对已评审决策和生命周期历史的治理作用。

**使用“智能体决策留痕工作流”。** 这是完整本地化表达，但“留痕”偏向合规语境，“智能体”对目标读者也不如既有术语 `AI Agent` 容易识别。

**只提供一条带模式占位符的通用提示语。** 维护内容更短，但读者仍需记住模式标识和语义。三条明确提示语更符合复制即用场景。

**因为双语模式是兼容默认值，所以推荐双语模式。** 兼容行为用于保护未配置的现有项目，不应决定最佳的新项目接入体验。中文模式在活跃讨论期间避免翻译和 hash 更新，同时保留相同的锁定双语结果。

**只在中文 README 中提供提示语。** 这会违反仓库的双语文档同等权威策略，并使英文指南不完整。

## 验证

更新 README 双语对及其真实 Git blob hash 后，`node scripts/verify-doc-i18n.mjs` 验证通过全部三组受管双语文档。此 Note 仍作为双语提案时，`node scripts/verify-agent-notes.mjs` 验证通过全部八组锁定 Note，`git diff --check` 未报告空白错误。

最终顺序反馈之前，`npm --prefix examples/agent-workflow-demo run check` 通过 Note 门禁、TypeScript 构建和全部 18 项测试；`npm --prefix examples/text-stats-workflow-demo run check` 通过 Note 门禁、TypeScript 构建和全部 25 项测试。后续变更只调整三种文档选项和提示语的顺序，聚焦文档与 Note 门禁随后再次通过。

项目负责人在实施前批准提案，选择中文模式作为新项目推荐选项，确定中文—英文—双语的最终展示顺序，并于 2026-08-30 接受通过验证的实施结果。

## 后果

读者可以直接复制一条完整提示语，不再需要自行把工作流语义转换为 Agent 请求。中文优先接入获得醒目的推荐标记，纯英文和持续双语起草仍作为同等支持的选项。缺少配置的现有项目继续采用双语兼容默认值。

较长提示语可能随工作流细节变化而漂移，因此它们紧邻权威接入清单，并要求用户遵循上游最新说明。“新项目推荐”与“缺少配置时的兼容默认值”继续明确区分。中文展示名是描述性品牌，不是仓库重命名。
