# Agent Note：按后缀统计目录行数

Status: implemented

[English](2026-08-24-directory-line-count-by-extension.md) | 中文

## 问题

现有 `text-stats <file>` 命令汇总一个 UTF-8 文件。用户还需要统计目录下选定源代码和文档文件类型的逻辑行数，并可选择包含嵌套目录。该功能需要明确默认值、后缀匹配、遍历、排序、失败和输出规则，使重复运行具有确定性。

## 决策

现有单文件调用方式及其三行输出保持不变。当第一个位置路径是目录时，命令支持以下调用方式：

```text
text-stats <directory> [--ext <extension>]... [--no-recursive]
```

目录扫描默认递归包含后代目录。`--no-recursive` 将扫描限制为直接子文件。遍历永不跟随符号链接。隐藏文件和隐藏目录与其他条目同等处理；不存在 `node_modules` 等隐式排除项。

没有 `--ext` 选项时，扫描 `.ts`、`.tsx`、`.js`、`.jsx`、`.mjs`、`.cjs`、`.json`、`.md`、`.css` 和 `.html` 文件。每个 `--ext` 都要求一个以 `.` 开头的非空后缀。一个或多个显式 `--ext` 值整体替换默认集合。重复后缀只采用一次，匹配文件名最终后缀时不区分大小写。

每个匹配的普通文件按 UTF-8 读取，并采用现有逻辑行规则计数：空文件为零行，LF 和 CRLF 各自分隔逻辑行，末尾分隔符不增加空行，中间空白行计数。目录输出先按照相对于请求目录、使用斜杠分隔的路径进行序数排序并列出匹配文件，随后输出总计：

```text
src/index.ts: 24
test/index.test.ts: 31
Files: 2
Lines: 55
```

没有匹配项时，只输出 `Files: 0` 和 `Lines: 0`。无效选项、多余位置路径、路径不存在、目录条目不可读或匹配文件不可读时，命令失败且没有 stdout，在 stderr 输出简洁错误，并以非零状态退出。命令不创建或修改文件。

实现分离选项解析、目录发现和输出格式化。`parseCliArguments` 负责默认值和语法验证，`countDirectory` 负责遍历和逻辑行汇总，`runCli` 按路径类型分派并格式化输出。测试使用临时目录树和真实构建子进程。

## 考虑过的替代方案

**要求使用 `--recursive`。** 这使默认操作范围受限，但会让主要的代码库全量统计场景必须增加选项。默认递归符合请求的工作方式，同时 `--no-recursive` 保留直接子文件扫描能力。

**使用逗号分隔后缀。** 它能缩短部分命令，但需要转义和空项规则。重复选项含义明确，并能自然组合于 shell。

**将显式后缀添加到默认值。** 这会让只请求一种文件类型的操作意外扩大范围。显式值替换默认值使选项含义直接。

**只输出总行数。** 这种方式紧凑，但无法证明哪些文件参与统计。排序后的逐文件行让匹配和总计可检查。

**自动排除隐藏目录和依赖目录。** 这种策略与生态系统相关，可能静默遗漏请求内容。本提案采用字面遍历；未来可单独提议包含和排除控制。

**跟随符号链接。** 这可能包含请求目录树之外的内容并产生循环。不跟随链接可得到有限且局部的扫描。

## 验证

`npm run check` 验证两组双语 Agent Note、编译严格 TypeScript 程序，并通过二十五项 Node.js 测试。四项解析器测试覆盖默认后缀、默认递归、重复后缀不区分大小写替换、`--no-recursive`、选项顺序和无效语法。五项目录测试覆盖默认递归、直接子文件扫描、多后缀、零匹配、相对路径排序、隐藏目录、符号链接、缺失路径和普通文件拒绝。七项 CLI 测试覆盖单文件输出不变、目录明细与总计、非递归零匹配、文件使用目录选项、参数缺失和过多，以及真实文件和目录子进程。原有九项基础设施、纯计数和文件访问测试也全部通过。

第一次 CLI 聚焦运行通过七项中的六项，并暴露了既有缺失文件错误的回归：路径分派将 `File does not exist` 改成了 `Path does not exist`。实现现在为不带目录选项的调用保留原错误，而为带目录选项的调用使用通用路径措辞。重复运行 CLI 专项后七项全部通过，随后完整检查通过全部二十五项测试。

## 后果

用户现在可以检查目录树中选定文件类型的行数，同时保留原有单文件行数、词数和字符数汇总。默认递归支持代码库全量度量，`--no-recursive` 将扫描限制为直接子文件，排序后的逐文件行使总计可检查。

大型目录树需要读取每个目录条目，并完整读取每个匹配文件，因此运行时间和内存使用随代码库规模及最大匹配文件增长。除非用户限制递归，否则字面遍历会包含依赖、生成和隐藏目录。不区分大小写的匹配可能包含大小写敏感生态认为不常规的文件。Node 的 UTF-8 解码会替换畸形字节序列，遍历期间发生的文件系统变更可能导致读取失败，而不是得到快照一致的结果。
