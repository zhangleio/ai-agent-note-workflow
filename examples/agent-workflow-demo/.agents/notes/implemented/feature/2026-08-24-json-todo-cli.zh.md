# Agent Note：JSON 待办 CLI

Status: implemented

[English](2026-08-24-json-todo-cli.md) | 中文

## 问题

这个演示需要一项能在单个评审周期内实现的小功能，同时仍要涉及明确的产品范围、持久化、命令解析、测试和持久决策记录。

## 决策

TypeScript CLI 首版恰好提供三个命令：`add`、`list` 和 `done`。它将待办存入 JSON 文件，并使用 Node.js 的 `parseArgs` 解析命令行参数。存储层与命令层相互分离，因此无需启动子进程即可测试持久化行为。

首版不包含删除或批量清理。每条待办都有稳定的数字标识符、文本、创建时间和完成状态。写入通过同目录临时文件替换 JSON 文档。文档不存在时读取为空的版本化文档；JSON 格式错误或文档结构无效时失败，且不替换源文档。当前文档格式和历史标识符规则由 [持久待办归档](../architecture/2026-08-24-durable-todo-archive.md) 决定。

## 考虑过的替代方案

**包含 `remove` 和 `clear`。** 未选择这些命令，因为它们会在基本生命周期得到验证前引入破坏性行为。它们可以另行提出，并明确确认机制和缺失 ID 的语义。

**使用 SQLite。** SQLite 提供事务和更好的查询扩展能力，但会引入原生或 WASM 依赖以及前三个命令并不需要的 schema 迁移策略。

**使用 Commander。** Commander 提供完善的子命令 API，但 Node.js 标准库的 `parseArgs` 足以支持这个刻意保持较小的命令集合，并避免运行时依赖。

**手写参数解析。** 手工解析最初看起来简单，但需要自行负责选项终止、缺失值以及帮助与错误的一致性。`parseArgs` 已经提供这些机制。

**只在内存中保存待办。** 这样可以避开存储失败行为，但 CLI 进程会在每个命令后退出，因此无法演示真实的待办生命周期。

## 验证

`npm run check` 验证 Agent Note 生命周期和必需章节，编译严格 TypeScript 程序，并运行聚焦的 Node.js 测试套件。测试持续覆盖 add/list/done 持久化、文件缺失、未知标识符不修改数据、畸形 JSON 不替换以及无效命令参数，并包含后续的归档覆盖。

第一次检查发现 TypeScript 6 不会隐式包含已安装的 Node 声明。项目现在显式声明 `types: ["node"]`，同一套完整检查可以通过。

## 后果

CLI 没有运行时依赖，数据保持人类可读。命令处理与存储分离，使行为可直接测试；临时文件替换则避免有意暴露只写入一部分的 JSON。

每次写入的复杂度仍与待办数量线性相关。并发进程可能互相覆盖，因为临时文件替换不是跨进程事务。已接受的首版明确记录这些限制，而不是在出现需求前增加数据库和锁定复杂度。
