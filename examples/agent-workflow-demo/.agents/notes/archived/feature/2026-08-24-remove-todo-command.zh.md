# Agent Note：删除待办命令

Status: implemented

[English](2026-08-24-remove-todo-command.md) | 中文

已被[持久待办归档](../../implemented/architecture/2026-08-24-durable-todo-archive.md)取代。本 Note 记录以前交付的永久删除和标识符复用决策；它不是当前命令权威。`remove` 现在不执行写入，并引导调用方使用 `archive`。

## 问题

首版可以创建和完成待办，但无法删除过时、重复或误输入的项目。增加破坏性行为需要明确决定确认机制、缺失标识符以及完成状态是否限制删除。

## 决策

以下决策描述持久归档取代它之前已经交付的行为。

CLI 提供 `remove <id>` 作为第四个命令。有效调用会立即删除匹配的待办，并输出 `Removed todo <id>.`。该命令可以删除开放或已完成待办。

无效标识符或文档中不存在的标识符会失败且不写入文件。实现复用现有的已验证 JSON 读取和临时文件替换；存储的待办结构不变。删除项目不会重新编号剩余待办。

标识符只在当前文档中唯一。`add` 分配比剩余最大标识符大一的值，因此删除当前最大值后，后续待办可以复用该标识符。这样可保持数组文档不变，并避免仅为历史标识符唯一性引入格式迁移。

## 考虑过的替代方案

**要求 `--yes`。** 这会增加防止意外删除的保护，但显式的 `remove <id>` 命令已经表达破坏性意图。增加标志会让脚本更繁琐，却不能防止选择错误标识符。

**使用 `y/N` 交互提示。** 交互确认很常见，但会使自动化、重定向输入、取消和测试更复杂。CLI 保持非交互式。

**将缺失标识符视为幂等成功。** 这可以简化清理脚本，但也会隐藏过时或误输入的标识符。现有 `done` 命令会报告缺失标识符，因此保持相同行为可让命令语义更可预测。

**只删除已完成待办。** 这样可以保护开放工作，但会把生命周期策略混入明确删除操作。用户可能合理地删除过时的开放项目。

**持久化单调 `nextId`。** 这样可以防止标识符复用，但会把 JSON 文档从数组改成对象，或增加独立元数据和迁移行为。已接受需求只要求标识符在当前待办中唯一。

**同时增加 `clear`。** 批量删除具有独立的范围、筛选和确认问题，不属于本决策。

## 验证

`npm run check` 验证两篇 Agent Note、编译严格 TypeScript 程序，并运行八项 Node.js 行为测试。remove 专项测试证明开放和已完成待办都可删除且不重新编号，未知标识符保持文档逐字节不变，删除最大标识符后下一个 `add` 可以复用该值。无效 remove 参数也通过命令用法路径失败。

## 后果

该命令保持可脚本化，并与 `done` 的缺失标识符行为一致。它不增加存储迁移或运行时依赖，并继续使用现有临时文件替换。

删除没有应用级撤销或确认。删除最大标识符后可以复用，因此外部引用不能把标识符视为永久历史身份。全量文档重写保留现有并发写入者限制。
